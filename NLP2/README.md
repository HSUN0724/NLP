# NLP HOMEWORK2：土味情話多輪對話專家（LoRA 微調）

從 Hugging Face 下載開源對話模型 **Qwen2.5-1.5B-Instruct**，用自己整理的「土味情話」多輪對話語料做 **LoRA 微調**，
讓模型變成一位會「一步一步教你怎麼接話」的土味情話專家，並可以進行多輪對話。

---

## 1. 專案目標

| 項目 | 內容 |
| --- | --- |
| 基底模型 | [`Qwen/Qwen2.5-1.5B-Instruct`](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)（中文能力好、1.5B 參數，8GB 顯卡可訓練） |
| 微調方法 | LoRA（PEFT），只訓練約 1% 參數 |
| 任務 | 多輪對話：「土味情話」專家 |
| 語料 | 自行整理的 57 段多輪對話、219 輪（每段 2～5 輪） |
| 訓練硬體 | NVIDIA GeForce RTX 5050 Laptop GPU（8GB） |

### System Prompt

```text
你是一個土味情話高手，你會以親切、溫和又帶點俏皮的口吻來回答使用者的問題，
擅長把日常話題變成讓人會心一笑的情話，並一步一步教使用者怎麼接話。
```

可以在執行時用 `--system "..."` 自訂其他情境（例如改成「幽默笑話專家」）。

## 3. 語料（Corpus）怎麼來的

1. **與 AI 平台討論**：和 ChatGPT / Claude / Gemini 等 AI 反覆討論「某個日常主題（天氣、咖啡、捷運、程式……）可以怎麼接土味情話」，
   要求它以「使用者追問 → 專家再接一句」的方式延伸成多輪對話。
2. **網路蒐集**：參考網路上流傳的土味情話、諧音梗，改寫成對話形式。
3. **人工整理**：刪掉重複、太油膩或不得體的句子，統一成「專家教使用者怎麼回」的口吻。

整理後存成 `data/raw_dialogues.txt`，格式如下（每段以 `### 主題` 開頭）：

```text
### 咖啡
你：我想約喜歡的人喝咖啡，有什麼好說法？
專家：你可以問她「妳喜歡喝什麼咖啡？」
你：她說「拿鐵」。
專家：那你就說「好巧，我喜歡的也是妳這一杯」。
```

`scripts/build_dataset.py` 會檢查每段是否「你／專家」交替、至少 2 輪，然後轉成 Hugging Face chat 格式：

```json
{"topic": "咖啡", "messages": [
  {"role": "system", "content": "你是一個土味情話高手……"},
  {"role": "user", "content": "我想約喜歡的人喝咖啡，有什麼好說法？"},
  {"role": "assistant", "content": "你可以問她「妳喜歡喝什麼咖啡？」"},
  ...
]}
```

語料涵蓋的主題：長相、天氣、咖啡、數學、物理、化學、程式、捷運、便利商店、星座、失眠、考試、火鍋、珍奶、生日、遊戲、健身、貓、颱風、電影、上班、保險、告白被拒、吵架和好……共 57 個。

## 4. 方法說明

### 4.1 LoRA 微調

LoRA 會凍結原本的模型權重，只在注意力層與 MLP 層（`q/k/v/o_proj`、`gate/up/down_proj`）旁邊加上小的低秩矩陣來訓練，
因此在 8GB 顯卡上也能微調 1.5B 模型，訓練後只需儲存幾十 MB 的 adapter。

### 4.2 只對「專家的回答」計算 loss

多輪對話中，模型應該學的是「怎麼回答」，而不是背使用者的問題。`train.py` 的 `encode()` 會：

1. 用模型的 chat template 把整段對話轉成 token；
2. 找出每一句 `assistant` 回答對應的 token 範圍；
3. 只有這些 token 計算 loss，`system`、`user` 的 token 標成 `-100`（忽略）。

這樣每一段 5 輪的對話，模型會同時學到第 1～5 輪在「看到前面對話脈絡」下要怎麼接，也就是**多輪對話能力**。

### 4.3 超參數

| 參數 | 值 |
| --- | --- |
| epochs | 5 |
| batch size | 4 |
| learning rate | 2e-4（cosine，10% warmup） |
| LoRA r / alpha / dropout | 16 / 32 / 0.05 |
| 精度 | bfloat16 + gradient checkpointing |
| max length | 512 tokens |

## 5. 操作步驟（一步一步）

### Step 1：安裝環境

需要 Python 3.10+ 與支援 CUDA 的 PyTorch（請依自己的顯卡到 [pytorch.org](https://pytorch.org/get-started/locally/) 選擇安裝指令）。

```bash
git clone https://github.com/HSUN0724/NLP.git
cd NLP/NLP2
pip install -r requirements.txt
```

### Step 2：準備語料

若要新增對話，直接編輯 `data/raw_dialogues.txt`，再執行：

```bash
python scripts/build_dataset.py
# 共 57 段對話、219 輪 → train 54 / eval 3
```

### Step 3：LoRA 微調

```bash
python train.py
```

第一次執行會自動從 Hugging Face 下載模型（約 3GB）。訓練完成後 adapter 存在 `outputs/lora-tuwei/`。
顯卡記憶體不夠的話可以改用較小的模型：

```bash
python train.py --model Qwen/Qwen2.5-0.5B-Instruct
python chat.py  --model Qwen/Qwen2.5-0.5B-Instruct
```

### Step 4：多輪對話

```bash
python chat.py              # 互動模式，輸入 /reset 清空對話、/exit 離開
python chat.py --demo       # 自動跑作業題目中的示範對話
python chat.py --no_adapter # 使用未微調的原始模型，比較差異
```

## 6. 實驗結果

### 6.1 訓練過程

完整紀錄見 `train_log.txt`（可訓練參數 18.5M，佔全部參數 1.18%）。

| 階段 | train loss（最後一步） | eval loss |
| --- | --- | --- |
| 訓練前 | – | 2.9842 |
| epoch 1 | 2.1472 | 2.0897 |
| epoch 2 | 1.4808 | **2.0768** |
| epoch 3 | 0.8849 | 2.2181 |
| epoch 4 | 0.4238 | 2.5809 |
| epoch 5 | 0.4721 | 2.6044 |

- train loss 從 2.56 一路降到 0.47，表示模型確實學到了語料的口吻與句型。
- eval loss 在 epoch 2 最低，之後回升，代表語料量小（54 段）時後期有些 **overfitting**；
  之後可以改成 2～3 個 epoch，或擴充語料來改善。

執行 `python chat.py`（載入 LoRA adapter，temperature 0.7），以下為實際對話紀錄（未經修改）：

```text

你：要吃早餐嗎
專家：不急，等我們有空談起來再說。

你：談什麼
專家：就談妳最近最喜歡的一道菜是什么？

你：番茄炒蛋
```

**差異分析**

- **原始模型完全沒有土味情話**：8 輪對話裡沒有任何一句情話，就算使用者直接問「你怎麼都沒說土味情話給我」，
  它也只是道歉、說「以後會注意」，下一輪被說「你好無趣」時給的仍是一句普通的客套話。
  可見**只靠 system prompt 不足以讓 1.5B 模型進入角色**，LoRA 微調後幾乎每一輪都能把話題轉成情話。
- **原始模型的角色跑掉了**：它的回答像美食推薦或社群貼文，每一輪都加 emoji 和 `#hashtag`，
  甚至說「你得嚐嚐**我們的**紅豆包」，像是店員在推銷；微調後的回答是簡短的一兩句對話，沒有 emoji、hashtag。
- **繁簡體**：使用者用繁體提問，原始模型卻大多回簡體（「什么」「早餐计划」「红豆包」「听起来」）；
  微調後幾乎都是繁體，只偶爾出現「什么」，說明繁體語料也有修正模型的用字習慣。
- **多輪連貫性**：兩者都能記住上下文（早餐 → 咖啡廳 → 遊樂園），但原始模型只是順著話題給建議，
  微調後則會延續同一個意象（遊樂園 → 心房 → 滑梯）、被吐槽時也會順著再接一句情話。
- **共同的不足**：在閒聊模式下，兩者都沒有真正做到「一步一步教使用者怎麼接話」，這部分還需要更多教學口吻的語料。

### 6.4 成效分析

**做得好的地方**

- **土味情話風格明顯**：幾乎每一輪都能把日常話題（早餐、咖啡、遊樂園）轉成情話，例如
  「加滿了一輩子的想念」、「我的心房……只有一個出口：靠近妳的那一邊」。
- **學到語料的句型**：「好巧，我這杯也是冰的」直接呼應語料中咖啡主題的「好巧，我喜歡的也是妳這一杯」，
  可以看出 LoRA 微調確實把語料的套路教給了模型。
- **多輪對話連貫**：12 輪對話都能接住上一句，例如被說「好土」「太誇張囉」時，會順著吐槽再接一句，而不是重新開話題；
  「遊樂園 → 心房 → 滑梯」也能延續同一個意象。
- **口吻親切俏皮**，符合 system prompt 設定。

**還不足的地方**

- **部分邏輯跳躍**：「冷開水」「我怕一熱就變 iced 了」「更適合我們的時區」語意不太通順，屬於 1.5B 小模型的創意上限。
- **偶爾混入簡體字或英文**（「什么」、「iced」），是 Qwen 原始模型的習慣（原始模型大多直接回簡體，見 6.3），
  微調後已大幅改善，但語料量還不足以完全約束成繁體。
- **角色偏向「直接撩」而非「教你怎麼接話」**：使用者直接閒聊時，模型會自己扮演對象跟使用者對話，
  較少出現 system prompt 中「一步一步教使用者」的說明口吻；若以「我想約她……該怎麼說？」的方式提問，比較能觸發教學模式。
- 「留給妳自己後悔吧」語氣稍嫌嗆，與「溫和」的設定略有落差。

## 7. 心得與可改進方向

- **微調是必要的**：同樣的 system prompt，原始模型完全不會說土味情話，還會跑成加 hashtag 的推薦貼文（見 6.3）；
  只用 54 段語料做 LoRA，就能讓模型穩定進入角色。
- **只算 assistant loss** 很重要：模型才不會學著「替使用者說話」，回答也比較會在適當長度停下來。
- 語料量（57 段）不算大，模型能學到「專家教你接話」的口吻與格式，但遇到語料沒有的主題時，梗的品質仍依賴原始模型的能力。
- 可改進：
  1. 持續和 AI 平台討論擴充語料到數百段，並加入更多不同的使用者追問方式；
  2. 加入「幽默笑話」等其他風格，用不同 system prompt 區分；
  3. 換更大的模型（如 Qwen2.5-3B/7B 搭配 4-bit QLoRA）提升創意與流暢度。
